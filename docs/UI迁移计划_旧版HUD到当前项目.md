# ASW 旧版 UI 迁移计划

> 状态：已实施（2026-07-16）  
> 目标项目：Arcane Stationery Workshop（Godot 4.7 / C#）  
> 基准分辨率：960 × 540，当前窗口输出为 1920 × 1080  
> 参考：用户提供的旧版战斗截图、`assets/ui`、`assets/fonts`

## 1. 本轮边界

本文确定迁移方向、交互契约、数据依赖、文件结构与验收标准；审阅通过后的第一版实现已经接入当前主场景。

本次计划覆盖：

- 左上角状态 HUD；
- 顶部中央与怪潮 `Cycle Duration` 同步的时间槽；
- 固定三个武器槽；
- 武器技能 CD 的数字与逆时针阴影遮罩；
- 全武器共享技能槽；
- 底部装备栏；
- Tab 背包及鼠标装备、卸下、交换、丢弃；
- 背包内额外武器的带出解锁契约；
- 当前尚无玩法数据的楼层、房间探索度与污染值占位策略。

本轮不扩展：小地图、房间目标、撤离倒计时、撤离面板、结算面板、污染值玩法效果、多房间探索算法。已有 Clear / LevelUpPannel 资产留待各自系统进入制作阶段后再迁移。

## 2. 旧版 UI 分析

### 2.1 值得保留的设计语言

- **斜切轮廓**：生命条与细条像削尖的笔、纸签或档案标签，符合“魔法文具”主题。
- **深蓝底 + 暖色边线**：深靛蓝面板压住高饱和场景，橙色描边提供清晰边界。
- **角落分区**：左上生存状态、左下武器、底部装备，中央战斗区域基本不被遮挡。
- **顶部时间读数**：旧版顶部中央时间槽提供稳定的怪潮节奏参照，位置远离其他高频信息，值得保留。
- **像素字体与整数缩放**：与 16-bit 场景统一，当前项目 960 × 540 内部分辨率可以在 1920 × 1080 下做整倍放大。
- **状态颜色分工**：HP、次级状态和技能条使用不同色相，扫视成本低。

### 2.2 不直接照搬的部分

- 旧版 `Lv.` / 经验语义不再成立，改为楼层与未来的房间探索度入口。
- 旧截图只有两个武器槽且排布较散；新项目固定为三个，必须在 1 / 2 / 3 键与槽位之间建立稳定映射。
- 旧底栏缺少清晰的选中、可装备、不可装备和丢弃反馈；新背包需要完整的鼠标状态。
- 旧版亮色渐变叠在高频像素背景上时文字对比不稳定；数值文本需要深色底、1 px 描边或阴影。
- 当前没有货币统计和多房间逻辑，不迁移无数据支撑的装饰性字段；顶部时间槽已有怪潮时间轴作为数据来源，应纳入迁移。

## 3. 当前项目现状与迁移影响

### 3.1 可直接复用

- `WeaponManager` 已固定三个武器槽，并提供武器装入、选中、移除信号。
- 已支持 1 / 2 / 3 和滚轮切换武器。
- `WeaponData` 已有 `DisplayName`、`Icon`、`Weight` 等基础字段。
- `Player` 已有 `CurrentHealth` / `MaxHealth`。
- `PaintStrokeController` 已实现右键按住绘制、松开结算和取消流程。
- `EnemySpawner` 已按 `_elapsedSeconds / Timeline.CycleDurationSeconds` 推进怪潮，并公开当前进度百分比和怪潮切换信号。
- 当前 `map_01_wave_timeline.tres` 的周期为 60 秒、非循环；怪潮在 0%、25%、55%、80% 切换。
- `assets/ui/HUD` 已提供菱形徽章、HP 主条、上下两条细条的底层、填充层和描边层。
- `assets/ui/CircularProgressIndicator` 已提供 96 × 96 环形底图和填充图。
- `assets/fonts/fusion-pixel-12px-monospaced-zh_hans.otf` 可覆盖中文像素文本。

### 3.2 必须先补的数据契约

- `Player` 目前没有生命值变化信号，HUD 无法可靠地事件驱动更新。
- 当前 `CurrentCharge` 位于每个 `WeaponInstance` 内，与“所有武器共享一个技能槽”冲突。
- 当前 `CooldownRemaining` 表示普通攻击冷却，不是用户要求展示的武器技能 CD。
- 项目尚无玩家污染值、楼层/房间探索状态、物资背包、重量、装备栏和武器解锁记录。
- 当前武器拾取在三个槽满时直接失败，不能把额外武器收入背包。
- `EnemySpawner._elapsedSeconds` 目前是私有字段，顶部时间槽还不能读取与怪潮完全相同的权威时间。
- 当前主场景没有独立的 `CanvasLayer` UI 根节点。

因此实现顺序必须先建立状态模型，再绑定视图；不采用每帧从场景树中猜节点、猜数值的临时做法。

## 4. 视觉方向

### 4.1 主题概念

**“异常档案仪表盘”**：UI 像压在战场画面上的文具档案标签、笔尖切面和墨迹刻度。它不是普通科幻 HUD，也不是通用奇幻面板。

### 4.2 色彩令牌

颜色从现有 HUD 像素资产中提取，并控制在六个主令牌内：

| 令牌 | 色值 | 用途 |
|---|---:|---|
| Archive Blue | `#0D3C70` | 面板深蓝、徽章基底 |
| Arcane Violet | `#7A1B77` | 污染、异常状态 |
| Health Magenta | `#D21E78` | HP 填充与受伤反馈 |
| Warning Coral | `#F97042` | 外轮廓、警告、选中重点 |
| Charge Gold | `#C9A40E` | 共享技能充能与就绪状态 |
| Ring Blue | `#5B6EE1` | 武器选中环、冷却辅助刻度 |

大面积背景使用近黑靛蓝并保持 80%～90% 不透明度；高饱和色只用于正在变化的状态。

### 4.3 字体角色

当前字体目录只有 Fusion Pixel，因此第一版不新增外部字体依赖：

- **状态标题**：Fusion Pixel，16 px，楼层、背包标题；
- **战斗数值**：Fusion Pixel，12 px，HP、CD 秒数、负重；
- **辅助说明**：Fusion Pixel，10～12 px，物品标签、操作提示。

所有字号以 960 × 540 内部分辨率为准，使用整数坐标、整数缩放和 1 px 深色描边，避免像素字体发虚。

### 4.4 标志性设计

武器技能进入 CD 后，深色遮罩从十二点方向开始，**逆时针擦除/回退**，像橡皮正在抹去武器图标；CD 结束时图标恢复完整颜色。该效果同时满足功能要求和“文具”主题，是本轮唯一重点动态效果。

除选中态和技能就绪态外，不增加持续呼吸光、漂浮粒子或多余闪烁。

## 5. HUD 布局

### 5.1 960 × 540 线框

```text
┌──────────────────────────────────────────────────────────────┐
│ ◇ 楼层 1 ── 污染值（暂为空）    [ 00:00 ]                  │
│       └──── HP 100 / 100                                    │
│         └── 共享技能充能                                    │
│                                                              │
│                       战斗可视区域                           │
│                                                              │
│                                                              │
│ [1 武器][2 武器][3 武器]     [装备1][2][3][4][5][6][7][8] │
└──────────────────────────────────────────────────────────────┘
```

- 左上状态簇锚定左上安全区，内部继续使用现有 276 × 105 HUD 图层的原生对齐关系。
- 怪潮时间槽独立锚定顶部中央，不跟随左上状态簇偏移，也不占用战斗准星区域。
- 左下三武器槽锚定左下，固定顺序 1 / 2 / 3，不因空槽重排。
- 底部装备栏锚定底边中央，第一版按旧截图使用 8 个可配置槽；数量由配置驱动，不写死在视图脚本中。
- UI 根节点使用 `CanvasLayer`，不跟随 `Camera2D` 位移。
- 基准安全边距为 12 px；`window/stretch/aspect="expand"` 下角落和底边各自保持锚点，不按屏幕宽度拉伸像素资产。

### 5.2 顶部中央怪潮时间槽

时间槽显示怪潮周期内已经经过的时间，格式为 `MM:SS`。它不是单独的生存计时器，也不是“距离下一波还有多久”的倒计时。

数据必须直接来自 `EnemySpawner`：

- `ElapsedSeconds`：当前周期已经推进的游戏时间；
- `CycleDurationSeconds`：当前时间轴的总周期；
- `IsRunning`：时间是否继续推进；
- `LoopTimeline`：达到周期末尾后归零循环，还是停在周期终点。

当前地图的实际对应关系为：

| 时间 | 周期进度 | 怪潮事件 |
|---:|---:|---|
| `00:00` | 0% | 小怪潮 |
| `00:15` | 25% | 墨潮逼近 |
| `00:33` | 55% | 失控墨潮 |
| `00:48` | 80% | 脆页偶加入 |
| `01:00` | 100% | 非循环时间轴停在终点 |

显示规则：

- 尚未启动时显示 `00:00`；
- 暂停或 `StopSpawning()` 时保持当前读数；
- `RestartTimeline()` 后回到 `00:00`；
- 非循环时间轴在 `Cycle Duration` 处停住；
- 循环时间轴与怪潮逻辑同帧归零；
- 时间轴资源无效时显示 `--:--`，不显示伪造时间。

视觉上使用 Fusion Pixel 20 px、白色数字、1 px 深蓝描边和轻量斜切暗底；不增加额外进度环或持续闪烁，避免与武器 CD 的径向动态竞争。

顶部时间槽不能使用 `Time.GetTicksMsec()` 或自行累计另一个计时变量。绘制技能慢动作、Tab 暂停和场景重启时，它必须与 `EnemySpawner` 使用的游戏时间完全一致。

### 5.3 左上状态簇语义映射

现有文件名保留，但场景节点改用新语义命名，避免以后继续沿用 EXP / MP / PP 的旧含义。

| 现有资产组 | 新用途 | 当前显示 |
|---|---|---|
| `EXP-*` 菱形 | 楼层 / 未来房间探索入口 | `楼层 1` |
| `MP-*` 上方细条 | 玩家污染值 | 空条；只展示视觉占位，不产生玩法效果 |
| `HP-*` 主条 | HP | `当前 / 最大`，受伤实时更新 |
| `PP-*` 下方细条 | 全武器共享技能槽 | 0%～100%，满槽显示“就绪”强调 |

房间探索度的数据字段先定义为可空值 `RoomExplorationRatio`，当前不伪造百分比、不显示假进度。当前单房间版本只显示 `楼层 1`；未来接入多房间系统时，再让菱形或附属刻度显示探索比例。

污染值同样只保留 `0 / 100` 的占位状态与绑定接口；在玩法说明确定前，不让它影响伤害、移动、画面或结算。

### 5.4 条形进度实现方式

每条由三层组成：

1. `*-B`：暗色底；
2. `*-A`：填充遮罩；
3. `*-Line`：最上层描边。

使用一个通用横向进度 Shader，根据贴图 Alpha 作为形状蒙版，再根据 `ratio` 裁切填充。这样可以保留原资产的斜切像素轮廓，并在不重绘贴图的前提下统一语义颜色。

## 6. 三武器槽与共享技能规则

### 6.1 武器槽显示

每个槽固定显示：

- 左上角：该武器技能剩余 CD，格式为 `4.2` / `1.0` / 空；
- 中央：武器图标；
- 右下角：键位 `1` / `2` / `3`；
- 外框：空槽、已装备、当前选中、技能可用四种状态；
- 遮罩：技能 CD 比例的逆时针深色径向遮罩；
- 禁用态：没有武器时保留槽位轮廓，不显示伪造图标。

CD 在武器未选中时仍继续倒计时，切换武器不能冻结 CD。

### 6.2 区分普通攻击冷却与技能 CD

保留现有普通攻击冷却，不把它显示成技能 CD。新增明确字段：

- `WeaponData.SkillCooldownDuration`；
- `WeaponInstance.SkillCooldownRemaining`；
- `WeaponInstance.SkillCooldownRatio`。

技能成功结算后才启动该武器的技能 CD；取消绘制或无效笔迹不消耗共享充能，也不启动 CD。

### 6.3 全武器共享技能槽

新增独立的 `SharedSkillCharge` 玩家组件：

- `CurrentCharge`；
- `MaxCharge`；
- `ChargeRatio`；
- `IsReady`；
- `ChargeChanged` / `ReadyChanged` 信号；
- `AddCharge()` / `TryConsume()`。

武器自身不再持有独立技能充能。切换武器时，共享进度不变化；释放当前武器技能后统一消耗并重置。技能通过命中敌人来补充技能槽的值。

第一版默认解释为：**技能槽满后获得释放资格，玩家仍按现有鼠标右键进入绘制并在松开时结算，不自动替玩家触发技能。** 这是为了与当前绘制技能交互保持一致。

当前武器必须同时满足以下条件才能开始技能：

```text
共享技能槽已满
+ 当前武器技能 CD 为 0
+ 当前没有正在绘制
+ 当前武器拥有有效 PaintBrushData
```

## 7. 底部装备栏

第一版使用 8 个数据驱动槽位，保持旧截图的横向节奏，但重新明确状态：

- 空槽：深蓝底 + 低亮描边；
- 已装备物资：图标、堆叠数量、耐久/次数（若该物资有）；
- 当前鼠标悬停：暖橙描边；
- 不可使用/条件不足：降饱和，不用红色大叉遮挡图标；
- 快捷键在具体物资使用规则确定前不显示，避免承诺尚未接入的键位。

材料类物资只进入背包，不强制允许装备；只有声明 `IsEquipable` 或 `IsQuickUsable` 的物资才能进入装备栏。

## 8. Tab 背包

### 8.1 第一版布局

```text
┌ 背包 ─────────────────────── 负重 12.4 / 30.0 ┐
│ ┌──────── 8 × 6 网格 ───────┐ ┌ 物品详情 ─┐ │
│ │ 物资 / 装备 / 备用武器     │ │ 名称       │ │
│ │                             │ │ 重量/价值  │ │
│ │                             │ │ 污染/发现  │ │
│ └────────────────────────────┘ │ [装备]     │ │
│ 三武器槽 [1][2][3]             │ [丢弃]     │ │
│ 装备栏   [1][2][3][4][5][6][7][8]         │
└─────────────────────────────────────────────┘
```

### 8.2 打开与输入

- `Tab` 打开/关闭；`Esc` 关闭。
- 打开时显示鼠标，关闭时恢复战斗鼠标模式。
- 原型阶段默认暂停玩法树，背包 UI 使用 `ProcessMode.Always`；这样先验证装备和丢弃，不让实时战斗干扰鼠标操作。
- 背包打开时，武器切换、绘制技能、Q 丢弃等战斗输入不得穿透。

### 8.3 鼠标操作

- 左键：选择物品并显示详情。
- 左键拖拽：在背包格、装备栏和三个武器槽之间移动或交换。
- 右键：打开仅包含当前物品可执行操作的菜单，例如“装备”“卸下”“丢弃”。
- 丢弃通过菜单/详情按钮执行，不以“拖出窗口”作为唯一入口，减少误操作。
- 绑定的默认武器不可丢弃；按钮显示禁用原因。
- 向已有武器的槽位拖入新武器时执行交换：旧武器必须能回到背包，否则拒绝操作并保持原状态。
- 超过格子或重量上限时拒绝拾取/交换，并明确指出是“空间不足”还是“负重超限”。

### 8.4 背包模型

第一版建立可配置的 8 × 6 网格和最大负重，不把尺寸写死在 UI：

- `InventoryItemData`：ID、名称、图标、分类、格子尺寸、重量、价值、是否污染、是否可装备、最大堆叠；
- `InventoryEntry`：数据引用、数量、网格位置、旋转状态（第一版可先禁用旋转）；
- `InventoryWeaponEntry`：引用 `WeaponInstance`，保留武器独立 CD 与运行状态；
- `InventoryModel`：放入、移动、交换、堆叠、丢弃、重量和容量校验；
- `EquipmentModel`：三个武器槽和八个装备栏槽位的合法性校验。

额外武器拾取规则：三个武器槽都有武器时，拾取物进入背包，而不是像当前逻辑一样失败。是否在有空槽时自动装备，第一版沿用当前行为：优先装入第一个空武器槽，满槽后进入背包。

## 9. 未装备武器的带出解锁

解锁只在“成功撤离/带出”事务提交时发生，不在拾取、装备、丢弃或打开背包时发生。

仅统计成功撤离时仍位于背包中的 `InventoryWeaponEntry`；当前三把已装备武器不计入这条“额外未装备武器”规则。

每个 `WeaponId` 保存 `SuccessfulBackpackExtractionCount`：

| 成功带出次数 | 结果 |
|---:|---|
| 0 | 未解锁 |
| 第 1 次 | 解锁该武器 |
| 第 2 次 | 解锁并获取该武器的蓝图图纸 |
| 第 3 次及以后 | 获取蓝图 |

当前项目还没有撤离结算入口，因此本轮实现时先建立数据契约与可测试的 `CommitSuccessfulExtraction()`，不在单房间测试场景中伪造永久解锁。

## 12. 自动化测试重点

- `SharedSkillCharge`：上限、消费、未满拒绝、切武器不变；
- 技能 CD：有效技能才启动、未选中继续倒数、归零钳制；
- 怪潮时间槽：60 秒非循环、循环归零、停止保持、重启清零、无效时间轴空态；
- `InventoryModel`：占格、堆叠、交换、重量、回滚；
- 装备交换：背包无空间时不替换；
- 解锁进度：首次/再次/重复、失败撤离、幂等提交；
- UI 冒烟：三个武器槽固定存在，Tab 面板输入不穿透。

## 13. 风险与控制

| 风险 | 控制方式 |
|---|---|
| 把普通攻击 CD 误当技能 CD | 新旧字段分开命名、分开测试，HUD 只读 `SkillCooldownRemaining` |
| 共享技能槽与当前绘制代码耦合 | 充能独立为玩家组件，武器只请求消费 |
| 背包交换吞物品 | 所有移动先校验后提交，失败保持原快照 |
| 像素 UI 在宽屏发虚 | 960 × 540 基准、整数坐标、最近邻过滤、角落锚定而非拉伸 |
| 污染/探索机制未定义导致返工 | 只做可空数据契约与空态，不写玩法效果 |
| HUD 时间与怪潮产生漂移 | 只读取 `EnemySpawner.ElapsedSeconds`，禁止 UI 自建计时器 |
| HUD 过度抢画面 | 高饱和色只用于当前状态，持续变化只限真实时间、进度与 CD |

## 14. 审阅时需要确认的三项默认决定

1. **共享技能满槽**：默认是“允许玩家用右键释放”，不是自动触发。
2. **Tab 背包**：原型阶段默认暂停战斗，并阻断战斗输入。
3. **装备栏数量**：默认 8 槽，数据驱动，后续可调整。

若以上三项确认，其余实现可以按阶段 A → F 直接推进。
